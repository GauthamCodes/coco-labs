# Lab 4 (Search) — evidence

Phase 5's Gazebo matrix: the searching mission, told only a colour, in a
fresh simulator per run, never `--fast`. Generated by
`docs/data/p05_evidence.py` from the raw run directories; every number in
`docs/labs/LAB4_SEARCH.md` and `docs/RESULTS.md` "COCO Lab Phase 5" that is
marked (measured) comes from here.

| path | what |
|---|---|
| `results.json` | the matrix table (what the Lab 4 page shows): one row per run directory, void runs listed and never scored |
| `runs/<name>.json` | one digest per run: what the robot was told, the episode (manifest — evaluator side), every look and what it saw, the FSM timeline in simulator seconds, outcome, lift, home error, relocalisations, recoveries, runner checks, commit, bag hash |
| `replay/p05_matrix/` | search bundle 1.0 (`docs/labs/SEARCH_FORMAT.md`): every run that looked at least once, rebuilt from its looks alone by `coco_lab.regionsearch.replay_search` on the problem the mission built. The policy must choose every bay the robot chose, or the extractor stops. The truth is in each run's evaluator block, which replay never reads |

Raw evidence (not committed; ~20 MB per run, mostly the rosbag) stays in
`~/coco_lab_runs/lab4/matrix/<name>/`: `runner.log` (every bring-up and
command-chain check), `mission.log`, `manifest.json`,
`spawned_manifest.json`, `readback_spawn.json`, `region_params.txt` and
`search_params.txt` (what the robot side was given), `search_stream.txt`,
`state_stream.txt`, `perception_status.txt`, `ramp_status.txt`,
`hrec.csv`, `bag/` (MCAP: `/mission/state`, `/mission/search`,
`/mission/search_region`, the status topics, ground-truth odometry),
`bag_timeline.json`, `cmdpath/`, `result.json`.

## Reproduce

```bash
# a COCO-only overlay of this tree (the worktree path has parentheses that
# break colcon/gz quoting, so Phase 5 used a copy: ~/coco_search_ws)
scripts/build_overlay.sh ~/coco_search_ws
# copy this tree to ~/coco_search_ws/src/coco-labs first: p05_run_one.sh
# runs the runner FROM that copy with COCO_WS=~/coco_search_ws
# the 16 runs, resumable; one fresh simulator each, ROS domain 64
docs/data/p05_matrix.sh
# per run, the FSM timeline in simulator seconds (needs ROS: rosbag2_py)
python3 docs/data/p05_bagtimes.py ~/coco_lab_runs/lab4/matrix/*/
# the committed evidence
python3 docs/data/p05_evidence.py ~/coco_lab_runs/lab4/matrix
```

One run alone: `docs/data/p05_search_run.sh OUT LEVEL SEED COLOUR [ORDER]`
(ORDER, e.g. `bay_4,bay_1`, runs a given order instead of coco_lab's).

## The plan (fixed before any run)

Policy order at the assumed d = 0.9: bay_3, bay_4, bay_2, bay_1
(`coco_lab/test/test_regionsearch.py::test_the_arena_order_when_the_camera_can_miss_is_not_nearest_first`).
FIXED layout: red bay_1, green bay_2, blue bay_3, yellow bay_4.

| group | runs | what |
|---|---|---|
| A fixed | 4 | FIXED, each colour, the robot's policy: found at look 4, 3, 1, 2 |
| B colours | 4 | COLOURS, red, the first seed from 1 that puts red in each bay (bay_1 5, bay_2 1, bay_3 7, bay_4 2) — chosen on placement only |
| D negative first region | 4 | POSITIONS, red, seeds 1–4 (red in bay_2, bay_4, bay_2, bay_2 — never the first bay searched) |
| C search orders | 4 | FIXED green (identical placement to A2), given orders: `bay_3` (stop after the first bay), nearest-first `bay_3,bay_2,bay_1,bay_4`, most-likely-first `bay_1,bay_2,bay_3,bay_4`, `bay_4,bay_1,bay_2,bay_3` |

16 runs is an inventory, not a rate.
