# ADR 0003 — The v1 archive: built from its tag at deploy time (M2.10)

- **Status:** accepted, 2026-10-10 (M2.10). Gautham may overrule it at the
  M2 review; the alternatives below are each a small change.
- **Evidence class of every number here:** MODEL (the build tooling and the
  browser), measured on the development laptop.
- **Evidence:** `docs/v2/data/m2/m210/` — `browser/v1_links_check.json`
  (every v1 URL form, Chromium) and `v1_archive_build.json` (two builds of
  the archive, compared).

## Context

M2 retires the v1 lab views from `main` (M2 prompt, section 0 item 5, and
M2.10): a frozen v1 build lives at `/v1/`, built from the tag
`coco-lab-v1-final` (= `3571169`), and **every old URL keeps working**. The
prompt leaves open how the frozen build is stored. Constraints:

- the deploy is GitHub Pages from one artifact (`lab.yml`), and the agent
  never deploys by hand or edits a release;
- nothing may delete evidence, a release or a working public URL;
- the archive must be what the tag is — not a copy that drifts.

## Options

| | How `/v1/` is produced | For | Against |
|---|---|---|---|
| **A. Build from the tag at deploy time** (chosen) | `lab_web/tools/build_v1_archive.sh` clones the tag (depth 1, from the repository itself), runs the tag's OWN `build_catalog.py`, `npm ci` on its own lockfile and `vite build` with `LAB_BASE=/coco-labs/v1/`, runs the tag's own dist check, and copies `dist/` to `lab_web/dist/v1/` in the Pages artifact | nothing new is stored; the archive is by construction the tag's build; the script refuses any commit but `3571169` | every deploy repeats the build (108 s measured locally) and needs the npm registry to still serve the pins in the tag's lockfile |
| B. Commit the built files | the 23 MB `dist/` committed to the repository (a directory or an orphan branch) | immune to registry rot; no build at deploy | 23 MB of generated bytes in git history forever; a second copy of v1 to keep honest |
| C. A release asset | the built `dist/` attached to a GitHub release, downloaded at deploy | not in git history | the agent must not edit releases, and creating one is an outward action the prompt did not ask for |

## Decision

**A.** The tag is immutable and already carries everything needed to
rebuild it; storing its output again would add a copy whose only job is to
equal what the tag builds. The build script pins the commit, so a moved tag
fails the deploy loudly instead of serving something else.

## What was measured (local, this session)

- The archive builds from the tag in **108 s**, **23 MB, 78 files**; the
  tag's own `check_dist` passes (0 failures); every page and asset path is
  under `/coco-labs/v1/`.
- **Reproducibility:** two builds differ only in `provenance.created_utc`,
  the wall-clock stamp the tag's tools write into 13 bundle manifests and
  deliberately exclude from every content hash (`coco_lab/bundle.py`). Every
  content hash is identical; so the archive is the tag's content, stamped
  with its build time.
- **Every v1 URL form resolves with 0 console errors and 0 page errors**
  (`v1_links_check.json`, 22 forms, Chromium, the built site served with the
  archive at `v1/`): the five bare lab views land on their Learn missions;
  `?view=live` on the Live view (kept in `main` until M5); deep links into a
  lab (`loc=`, `scene=`, `map=`, `move=`, `search=`), `?view=exhibit`, share
  links with settings or map edits, `?v=1` alone and an unknown bundle land
  on `v1/` with their query intact and open the same v1 page; unchanged Lab 1
  bundle links open the bundle's converted run in the Arena. The routing is
  `lab_web/src/landing.ts`, unit-tested in `test/landing.test.ts`.
- Not a v1 URL form, and not checked: the archive's own Live tab
  (`v1/?view=live`) is v1-final's code, frozen; with no stack reachable it
  logs its connection attempts, as v1 did.

## Consequences

- `lab.yml`: the `lab-web` job builds the archive into the Pages artifact
  after its identical-build check (timeout 20 → 30 min); the browser job
  builds it too and runs `v1_links_check.mjs`.
- The v1 lab view code is removed from `main` (the commit lists every file);
  the site data it read (`build_catalog.py`'s catalog and bundles) stays,
  because the converters and the Learn missions read it.
- If the npm registry ever stops serving a pin in the tag's lockfile, the
  deploy fails at this step. The remedy is option B for that day, not a
  change to the tag.

## Amendment, 2026-10-10 (M2 review): the source commit is `9f58b83`

**What the review found.** The tag `coco-lab-v1-final` (= `3571169`) was
cut in M0.2, *before* M0's public fixes, so the archive built from it put
them back at `/v1/`:

- every view's Live tab read plain "Live" (M0.6 renamed it "Live Stack
  (simulated)", `dbf1f60`);
- the Search lab said "real robot" for the Gazebo stack (also `dbf1f60`);
- the Live view opened a WebSocket on load and logged
  `ERR_CONNECTION_REFUSED` console errors (M0's quiet probe, `40b6dc2`,
  opens none until `/healthz` answers).

The section above left `v1/?view=live` unchecked, so none of this was seen.
Measured on the tag's build: 22 of 22 URL forms pass, **6 of 6 archive views
fail** (`docs/v2/data/m2/review/links/tag_build.json`).

**Decision (owner's ruling, 2026-10-10).** `/v1/` is built from **`9f58b83`**,
the M0 merge into `main`: v1's views with M0's public fixes and no M1 code.
`build_v1_archive.sh` fetches that commit (depth 1) and runs its own tooling
as before; it refuses nothing else because it builds nothing else. The tag
is unchanged and stays v1's freeze point.

**Measured on the `9f58b83` build:** 109 s, 23 MB; 22 of 22 URL forms and
**6 of 6 archive views** (Lab 1 Plan, Localise, Map, Search, Move, Live
Stack (simulated)) with 0 console errors, 0 page errors, no "real robot"
(`docs/v2/data/m2/review/links/9f58b83_build.json`). `v1_links_check.mjs`
now checks the six archive views too, in CI.

**Superseded in M3.0.** The owner has also decided (plan-change log,
2026-10-10) that the archive becomes a built artifact: built once from
`9f58b83`, its Pyodide self-hosted, committed to an orphan branch `v1-site`,
copied into the Pages artifact at a pinned commit and checked by checksum;
the build-from-source script becomes a weekly reproducibility check. Option
B above, chosen for the reason this ADR gave against A: a toolchain that
ages out from under the build.
