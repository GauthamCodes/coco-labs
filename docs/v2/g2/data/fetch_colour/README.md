# Fetch by colour — what was built and measured (owner request, 2026-10-24)

Gautham, 2026-10-24: *"I want there to be multiple rods like in the beginning, and the robot goes
to the colour of the rod we choose."* Evidence class **MODEL** (the Python Arena model, in CPython
and in the browser through Pyodide). Nothing here was run in Gazebo.

## What

- **Level** `coco_depot_colours_v1` (`worlds/coco_depot_colours_v1.yaml` and its canonical
  `.json`): the Depot exactly as `coco_depot_v1`, plus four rods. Generated by
  `worlds/tools/make_coco_depot_v1.py --variant colours` and `tools/g1/depot_json.py --variant colours`.
  The Depot's own files, its Fetch Rush rounds (r2/r3/r4), references and goldens are byte-identical
  (`coco_lab/test/test_fetch_colour.py` pins them by sha256).
- **Rods** — the catalog's four Stack targets (no new asset; `coco_config/coco_config/robot.py`
  TARGETS: same diameters, 0.158 m tall, 0.05 kg), in one row on the dispatch floor, 1 m apart,
  red to yellow west to east as the Stack's bays run red to yellow:

  | Colour | Rod | Catalog item | Diameter | At (world, m) |
  |---|---|---|---|---|
  | red | `rod_red` | can_small | 20 mm | (20, 8) |
  | green | `rod_green` | bottle_steel | 24 mm | (21, 8) |
  | blue | `rod_blue` | canister | 28 mm | (22, 8) |
  | yellow | `rod_yellow` | can_large | 32 mm | (23, 8) |

  The row is 2 m north of COCO's start pad (23, 6), south of the forklift lane (y ≥ 10) and of the
  aisle walker's lane (x 24.2, y ≥ 8.5), 1 m from `bad_too_wide` (19, 7.5). Every rod passes the
  World Spec v3 checks, is pickable, and has all 16 pre-grasp headings free.
- **Game** `fetch_colour` (`coco_lab/coco_lab/games.py`: `FetchColour`, `bot_fetch_colour`): one
  order, the chosen colour's rod → **Dispatch** (`dispatch_drop`, the drop zone nearest the row).
  Fetch Rush's machinery: deliveries, contacts, the timer, path efficiency, stars against the
  reference (★ delivered, ★★ as many net deliveries, ★★★ ranked at or above the reference).
  The start is the start pad, facing the middle of the row (126.9°), so all four rods are in view.
- **Rounds** `coco_lab/coco_lab/levels/coco_depot_colours_v1.fetch_colour.json`, written by
  `tools/g2/make_fetch_colour_rounds.py` (`--check` regenerates and compares; about 5 min).

## Browser runs (`browser/`)

`lab_web/tools/g2/fetch_colour_check.mjs`, 2026-10-24 (UTC), Chromium (Playwright) on the RTX 4050
(ANGLE, OpenGL ES 3.2), served `dist` on port 4192, laptop shared (load ≈ 8.5). For each colour:
the mode card's chip, PLAY, AUTO to the rod, GRAB, AUTO to Dispatch, DROP. Every run delivered
the chosen rod, 0 contacts, no page error; the chips gain `&planner=dijkstra` when that planner
is chosen and lose it on A*.

| Colour | Profile | Delivered | Time | Stars |
|---|---|---|---|---|
| red | desktop 1440 × 900 | rod_red | 74.3 s | ★★ |
| green | desktop | rod_green | 66.1 s | ★★ |
| blue | desktop | rod_blue | 64.8 s | ★★ |
| yellow | desktop | rod_yellow | 60.8 s | ★★ |
| blue | emulated Nothing Phone (1), landscape (viewport only, no CPU throttle) | rod_blue | 66.3 s | ★★ |

Driving with AUTO + GRAB is 4–8 s slower than the reference (AUTO drives to the rod and Grasp
Assist then approaches; the bot drives straight to the pre-grasp pose), so this way of playing
earns ★★, not ★★★. All five browser records replay in CPython (`coco_lab.games.play`) to the same
hash chain and scorecard (`browser/cpython_replay.json`).
