# R3.5 · Model vs ROS 2 — method (results PENDING)

**Status: PENDING.** The paired Gazebo + Nav2 runs (R3.4, `tools/r3/ros2_queue_r34.sh`) have not finished. This
page states the method only; it contains no results, and none may be quoted until `gap.json` is generated from

## The two evidence classes

- **MODEL**: COCO Lab's Python reference model (kinematic, differential drive, terrain following), natively or in
  the browser. Source: the committed R3.2 baselines, `docs/v2/r3/bench/<suite>/<family>/public/runs.jsonl`.
- **STACK**: the full ROS 2 Jazzy stack with Nav2 in Gazebo Harmonic, headless, one fresh simulator per session,
  never `--fast`, on AC and the balanced profile. **A simulation; no physical robot exists.** Raw runs:
  `~/coco_lab_runs/r3/r34/` (read-only evidence; checksummed here when committed).

Both run the **same scenarios** of COCO-Bench v1 (same world, start, goal and seed). The STACK side uses a
validated subset of each suite: the first ceil(n/3) scenarios of each difficulty tier, 20 per suite
(`ctrl-dynamic-30`: all 15 pairs under both actor rules), from `tools/r3/stack_scenarios.py`.

## What is paired

| family | MODEL | STACK | kind of pair |
| --- | --- | --- | --- |
| planning | A\* | the A\* starter exported as a ROS 2 node (`user_compute_path_to_pose`) | **same code** |
| planning | A\* | Nav2 Smac 2D (`GridBased`), stock and snapped | counterpart |
| planning | Dijkstra | Nav2 NavFn, stock and snapped | counterpart |
| planning | A\* | Nav2 Smac Hybrid-A\*, snapped | reference only (no model counterpart) |
| control | RPP | Nav2 Regulated Pure Pursuit | counterpart |
| control | DWA | Nav2 DWB | counterpart |
| control | MPPI | Nav2 MPPI | counterpart |
| localisation | MCL (+ injection) | AMCL; the particle-filter starter in AMCL's place | counterpart; same code |

A **same-code** pair measures what the stack adds around one algorithm. A **counterpart** pair compares Nav2's
own implementation with the model's reference of the same idea: a difference may come from the algorithm's
implementation as much as from the simulation.

STACK planners use the R3 Nav2 variants generated by `tools/r3/prepare_gazebo.py` (G2's derivation-5 files, with
Smac Hybrid-A\* added); STACK controllers use Nav2 Jazzy's bringup defaults with COCO's limits (0.3 m/s, 1.0 rad/s,
no reversing). Every change to the generated files is listed in each variant's `params_derivation.json`.

## Conventions

- **Snapping.** Nav2's planner server refuses a start or goal inside inflated cost; COCO Lab moves both to the
  nearest free cell (raw cost < 253, breadth first, 8-connected) before planning. STACK planning reports both:
  **stock** (as given) and **snapped** (the same rule applied to the live global costmap). Neither is hidden.
- **Actor rules (scenario rules, not physics).** In `ctrl-dynamic-30` each start/goal pair runs twice: the actors
  **yield** (they stop for COCO; Fetch Rush rules 5) and the actors **keep their schedule** (rules 4). In Gazebo the
  same rules drive the kinematic actors (`tools/g2/actor_scenario.py`; the keep-schedule variant sets the stop
  margin so that no hold is ever triggered).

## Measures

For every pair and suite, over the scenarios both sides ran:

- **Success.** Planning: a path was found. Control: the goal was reached (Nav2's `SUCCEEDED`; the model's
  FollowPath-like goal checker). Localisation: the goal was reached with the final error under the thresholds.
- **Repeats.** STACK runs three sessions (rep1–rep3); a scenario's STACK success is the **majority** over its
  repeats. Every repeat stays in the per-scenario rows.
- **Confusion table** (model × stack): both succeed, model only, stack only, neither.
- **Agreement** = (both + neither) / n.
- **Model optimistic** = model only / n (the model succeeds where ROS 2 fails).
  **Model pessimistic** = stack only / n.
- **Ratio** = STACK value / MODEL value per scenario solved by both (planning: path length; control: time to goal),
  the STACK value being the median of its successful repeats; the median ratio over scenarios is reported with
  its n.

## Limitations

- STACK is a simulation of the full ROS 2 stack, not hardware; Gazebo's contact physics, AMCL and Nav2's
  controllers are part of what is measured, so a gap mixes model simplifications with implementation
  differences.
- Counterpart pairs are not the same code; only the A\* starter pair isolates the stack's effect on one file.
- Subsets of 20 scenarios per suite (three repeats each) bound the precision of every rate; intervals are reported,
  and small differences are not read as findings.
- One robot, one world family (the Depot and its cluttered variant); the arena suite has no STACK subset.
- Known UNRESOLVED items carry over: in R3 Part A, one Depot goal (s086) lies 7.38 m from free space in Gazebo's
  live costmap although the model drew it with clearance.
