Comparing navigation algorithms ought to be simple: fix the map, the start, the goal and the seed,
change one algorithm, and measure. In practice a result also depends on a simulator version, a ROS
distribution, a costmap configuration, the speed of the machine and a seed that is often not
reported. Re-running a published comparison usually means rebuilding a software stack first, and a
small difference in any layer can change the outcome \cite{bonsignorio2015replicable}. Navigation
benchmarks exist \cite{perille2020barn,wen2020mrpb,heiden2021benchmr,kastner2022arenabench}, but
each is tied to a local installation, so reproducing a number means trusting that the installation
matches.

We ask how far one can get when the benchmark run itself is the reproducible artefact. \bench{}
runs a Python reference model of a differential-drive robot (planar kinematics with terrain
following, a simulated LiDAR, costmaps, global planners, local controllers and localisers),
unchanged, in any web browser through Pyodide \cite{pyodide}. Every run produces a chain of hashes
of the simulation state, and the same inputs must give the same chain in every engine and natively;
continuous integration checks that they do. A result is therefore a link that anyone can open and
re-run, and a disagreement is detectable rather than a matter of opinion.

A deterministic kinematic model is useful only if one knows how far its verdicts carry over to a
real robotics stack. We therefore pair it with the full ROS~2 navigation stack
\cite{macenski2022ros2,macenski2020marathon} in Gazebo \cite{koenig2004gazebo} on the same worlds and
scenarios, and report where the two agree and where they do not. No physical robot was used. Every
result is labelled \evclass{model} (the browser model) or \evclass{stack} (ROS~2 in Gazebo, a
simulation), and failures are reported rather than filtered.

Our contributions are:
\begin{itemize}
\item a browser-based, hash-verified navigation model whose runs reproduce exactly across
  \DetEngines{} engines and natively (\cref{sec:system});
\item \bench{} v1: \BenchSuites{} frozen suites with \BenchScenarios{} scenarios for global planning,
  local control, localisation and a full fetch task, with difficulty tiers defined by measurable
  features, generated datasheets, and held-out scenarios drawn from a secret outside the sandbox
  (\cref{sec:bench});
\item a ROS~2-shaped algorithm API and a sandboxed, verified leaderboard, with export of the same
  user file to a ROS~2 node (\cref{sec:system});
\item a comparison of the model with ROS~2 on shared scenarios, including a negative case study: an
  any-angle planner that wins in the model and fails every drive under Nav2's controller
  (\cref{sec:experiments}).
\end{itemize}
